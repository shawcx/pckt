# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`pckt` is a Python 3 library for building packets a layer at a time, chaining the layers into a full frame, decoding frames back into layers, and sending or capturing them through its own libpcap binding (`pckt.pcap`). The distribution name on PyPI would be `pckt` (unclaimed as of 2026-09).

## Layout

- **`pckt/layer.py`**: the `Layer` base class that every protocol subclasses (`ethernet.py`, `vlan.py`, `llc.py`, `arp.py`, `lldp.py`, `cdp.py`, `ip.py`, `ipv6.py`, `icmp.py`, `icmpv6.py`, `tcp.py`, `udp.py`, `layer7/dhcp.py`, `layer7/dhcpv6.py`, `layer7/dns.py`, `layer7/netbios.py`, `layer7/ssdp.py`).
  - Fields are declared in a `FIELDS` tuple of `(name, default)` pairs in wire order, and set with keyword constructors (`IP(dst='10.0.0.2')`). A layer's payload is another `Layer`, `bytes`, any object with `pack()`, or `None`.
  - `a / b` returns a **copy** of the chain with `b` appended as the innermost payload. `pkt[UDP]` finds a layer, and `UDP in pkt` tests for one.
  - A field left at its `None` default is computed when packing: lengths, header lengths (options get padded), checksums, and the next layer's ethertype, IP protocol or UDP ports. Those come from the payload class's `ETHERTYPE`/`IP_PROTO` attributes or its `udp_ports()` method. An explicitly set value is always packed as-is.
  - Each subclass implements `build(data, outer)`, which returns its header plus `data`, and `unpack(pkt)`, which returns the rest. TCP, UDP and ICMPv6 checksums call `outer.pseudo_header()` (implemented by `IP` and `IPv6`), so they're 0 when there's no enclosing IP layer.
  - `Cls.decode(bytes)` builds the whole chain. It finds the next class through `Layer.lookup()`, a registry of subclasses keyed by `ETHERTYPE`/`IP_PROTO`/`UDP_PORTS` (a tuple of values is allowed), and through the `subclass_for()` hook (e.g. ICMP echo types). Decoded fields are concrete values, so re-packing reproduces the input exactly; set a field to `None` to recompute it after editing. DNS is the exception to plain re-encoding: senders differ in which names they compress, so a decoded `DNS` keeps its original bytes and packs them until any field changes (see `_wire`).
  - MACs and payloads are `bytes` (MAC fields also accept `'aa:bb:..'` strings), and IP addresses are `str`. TCP's sequence number field is named `syn`. `DHCP.options` and `DHCPv6.options` are lists of `(code, bytes)` tuples, or raw bytes packed as-is; `DHCPv6` has `fqdn()` and `vendor_classes()`, and relay messages decode as `DHCPv6Relay`. `LLDP.tlvs` is a list of `(type, bytes)`, with `tlv()`, `capabilities()` and `management_addresses()` to read them; `CDP.tlvs` is the same, with `tlv()`, `capabilities()` and `addresses()`, and its checksum follows Cisco's odd-length quirk (`cdp_checksum()`, from Wireshark's `packet-cdp.c`). An `Ethernet` or `VLAN` type field up to 1500 is an 802.3 length (computed when the payload is `LLC`, and padding past it is dropped): `LLC` then `SNAP` (OUI and protocol ID; next layer by `SNAP_ID`, or by ethertype when the OUI is 0); both add their end marker when packing and keep what follows it as `padding`. `DNS` has `questions`/`answers`/`authority`/`additional` lists of `DNSQuestion`/`DNSRR` dataclasses. Their `data` is typed for A/AAAA/NS/CNAME/PTR/MX/SOA/SRV/TXT and raw bytes otherwise (including EDNS `OPT`). There's no DNS-over-TCP length prefix. `DNS` also decodes mDNS (5353) and LLMNR (5355); LLMNR's C and T flags are `aa` and `rd`. `NBNS` (137) subclasses `DNS`: the flag bits come from the `FLAGS` table, which it overrides to replace `z`/`ad`/`cd` with `broadcast`; names are first-level encoded (`NBNS.encode_name()`/`decode_name()`), and NB record data is a list of `(flags, address)`. `SSDP` (1900) has a `start` line and `headers`, a list of `'Name: value'` strings packed verbatim, read with `header()`. IPv6 extension headers are not decoded.
- **`src/pcapmodule.c`/`.h`**: the C extension `pckt.pcap`. The header holds the Python-facing surface (prototypes, method tables, type objects), `pcapmodule.c` the implementations, and `win32.c`, a fragment `#include`d at its bottom, the Windows-only ones.
  - pypcap3 (github.com/shawcx/pypcap3) was merged into this binding twice: its features up to 7430272 (October 2026) are ported, in pckt's call shapes rather than pypcap3's (`next()` and callbacks get `(data, ts, wirelen)`, not bytes plus a `header=` option; `findalldevs()`, `open_offline()`, `lib_version()` keep their names; wrong argument types raise `TypeError`). Its history is reached through the two "Merge pypcap3's history" commits (up to 2e1c711, and up to 7430272, which brings in no files).
  - Module functions are `findalldevs()` (`{name: {'description', 'flags', 'addresses', 'mac', 'ipv4', 'ipv6', 'ip', 'netmask', 'broadcast'}}`: `addresses` is `{'family', 'addr', 'netmask', 'broadcast', 'dstaddr'}` for each IPv4 and IPv6 address, `ipv4`/`ipv6` list them again, `ip`/`netmask`/`broadcast` are the first IPv4 address's, and those six keys appear only when known), `mac()`, `lookupnet()`, `open_live()`, `create()`, `open_offline()`, `open_dead()`, `compile()`, `lib_version()`, and name/number lookups for link types and timestamp types. The types are `Handle` (subclassable; `Handle()` has no device), `PacketIterator`, `BPFProgram`, `Dumper` and, on Windows, `SendQueue`. Import calls `pcap_init(PCAP_CHAR_ENC_UTF_8)`.
  - A `create()` handle takes `set_snaplen()`/`set_promisc()`/`set_timeout()`/`set_immediate_mode()`/`set_buffer_size()`/`set_rfmon()`/`set_tstamp_type()`/`set_tstamp_precision()` (and `set_protocol_linux()` on Linux) and then `activate()`; each returns `None` or a warning string. Until then `snapshot()`/`datalink()` raise, and the setters raise once it's active. `can_set_rfmon()` is `False` for handles not from `open_live()`/`create()` (`live`), since libpcap crashes on files.
  - `loop()` and `dispatch()` call `callback(data, ts, wirelen, *extra)` with the GIL released, taking it back per packet through `loop_ctx`; `dispatch()` returns how many it counted (macOS's libpcap returns 0 at the end of a file). `next()` returns `(data, ts, wirelen)`, `None` when nothing is available yet, and raises `EOFError` at the end of a file or after `breakloop()`. Iterating over a handle yields the same tuples, and ends at the end of a file, after `breakloop()`, or in non-blocking mode once nothing is ready. `sendpacket()`/`inject()` send the bytes unchanged.
  - Every method that touches `pd` starts with `PCAPCTX`. `loop()`, `dispatch()`, `next()` and iteration set `busy` while the GIL is released, and `BUSYCHECK` makes them, `close()` and `setfilter()` raise meanwhile, so a callback or another thread can't close or re-enter the `pcap_t`; `breakloop()` is deliberately unguarded.
  - Ctrl-C: the first blocked call installs a C SIGINT handler (`acquire_sigint()`) that calls `pcap_breakloop()` and chains to Python's, so the call raises `KeyboardInterrupt`; calls running at the same time can only be stopped with `breakloop()`. Nothing is hooked while SIGINT is ignored or default.
  - Capture files: `dump_open(file, append=False)` returns a `Dumper` whose header has the handle's link type and snaplen; `write(data, ts=None, wirelen=None)` truncates to that snaplen, and `ts` defaults to now. `loop(dumper)` writes from C with no Python per packet, keeping capture timestamps, and `loop(dumper.write)` gives the same file; the dumper's own `busy` stops `write()`/`close()` meanwhile. `open_offline()` and `dump_open()` take a path (str, bytes, PathLike), a file object or a descriptor (`parse_target()`). Descriptors are `dup()`ed, so the caller's stays open, and `open_offline()` releases the GIL while libpcap reads the header, since a pipe can block. In nanosecond mode (`precision=` on `open_offline()`/`open_dead()`, or `set_tstamp_precision()`) libpcap keeps nanoseconds in `tv_usec`, so timestamps scale by the handle's precision.
  - Filters: `setfilter()` takes an expression or a `BPFProgram`, and `compile()` (on a handle, or the module's through a temporary `open_dead()`) returns one: a sequence of `(code, jt, jf, k)` as `tcpdump -ddd` prints them, with `match(bytes)` and `instructions()` (`tcpdump -d`). `BPFProgram(instructions)` builds one, checked with `bpf_validate()`; `compiled` says whether `pcap_freecode()` or `PyMem_Free()` frees it. The netmask, only used by `ip broadcast`, is a dotted string or by default the device's from `pcap_lookupnet()` (`parse_netmask()`); `pcap_compile()` needs host byte order, though `pcap_lookupnet()` gives network order. Files have none, so `ip broadcast` needs `netmask=`.
  - On Windows (`win32.c`), `open_live()`/`create()`/`lookupnet()` also accept a connection name ("Ethernet") and `findalldevs()` reports it as `name`, descriptors become Windows handles (`dup_handle()`) since wpcap.dll may use another C runtime, and there's no `fileno()`. Npcap adds `setbuff()`, `setmintocopy()`, `setuserbuffer()`, `setmode()`, `stats_ex()`, `oid_get_request()`/`oid_set_request()`, `getevent()`, `SendQueue`/`sendqueue_transmit()` and rpcap: `open_remote()`, `find_remote()`, `createsrcstr()`/`parsesrcstr()`, `setsampling()` and active mode (`remoteact_accept()`, which `remoteact_cleanup()` stops from another thread, `remoteact_list()`, `remoteact_close()`). None of it has been run. It compiles with mingw-w64 against the Npcap SDK (`-D_UCRT`), apart from `_set_thread_local_invalid_parameter_handler`, which only MSVC's headers declare. On macOS (`__APPLE__` in `find_mac()`), processes that aren't root get `02:00:00:00:00:00` in place of the real address, so `mac()` raises `EPERM` and `findalldevs()` leaves `mac` out.
  - `pckt/pcap.pyi` types the module (`pckt/py.typed` marks the package). Update it with the C code: `test_pcap.py`'s `test_stub_matches_module` compares their names, and CI's `typing` job runs stubtest (allowlist in `stubtest-allowlist.txt`) and `mypy --strict test/typing_check.py` against an installed copy.
- **`pckt/capture.py`**: `packets(pd, interval)` yields packets plus a `None` every idle interval, using `select()` on `fileno()`. Use it when the caller needs periodic work: on Linux, libpcap ignores the capture timeout while the interface is idle, so `next()`/`loop()`/iteration can block until traffic arrives (Ctrl-C still interrupts them).
- **`pckt/stack/ghost.py`** (`python3 -m pckt.stack.ghost <dev> [--ip ...]`): a fake host that leases an address with DHCP (with retries) or uses `--ip`, and answers ARP and ping. `Ghost` takes an open handle so tests can drive it with a fake.
- **`pckt/mapping/passive.py`**: maps MAC → IPv4, IPv6, name, OS, vendor and LLDP details from ARP, DHCP requests, DHCPv6 client messages, neighbor discovery, mDNS and LLMNR responses, NetBIOS name registrations, SSDP, LLDP and CDP, live or with `--file`; all of it stays on the local link, unlike routed IP traffic. NetBIOS and DHCPv6 can also be unicast to a server, possibly through a router, so only broadcasts and multicasts are used. `PassiveMapper.process(frame)` is pure logic. An mDNS or LLMNR response names its sender only when one of its address records is the address it came from, which skips repeaters and sleep proxies answering for others. A NetBIOS registration names its sender only for a unique workstation (`<00>`) or server (`<20>`) name at the sender's address: `<1d>` and group names are the workgroup's, and `<03>` can be the user's. A name that differs only in case (NetBIOS's are upper case) doesn't replace the one already seen. `ssdp_os()` reads the OS from an SSDP `SERVER` header (`OS/version UPnP/1.x product/version`) or Chromium's DIAL search `USER-AGENT` (`product/version OS`); it's a guess, so it only fills in an OS no other source has found, and it's skipped when `LOCATION` isn't the sender's address (a proxy) or isn't a valid URL or the sender's MAC is known with another IPv4 address (multicast routed from another subnet). LLDP hosts are keyed by a MAC chassis ID, so a switch's ports merge into one host. CDP hosts are keyed by the sending MAC, and CDP only fills in fields no other source has given (`ipv6` is still added to), since devices sending both LLDP and CDP describe themselves differently in each. `dhcp_os()` takes the OS from the vendor class (option 60) when the client names itself (Windows, Android, busybox, dhcpcd's `uname`; `vendor_class_os()`, which DHCPv6's vendor class uses too), else from Apple's or Windows' parameter request list (option 55). Those rules were checked against Apple's `bootp` source and FingerBank's 2014 database.
- **`pckt.vendor(mac, full=False)`** looks up the bundled `pckt/manuf`, Wireshark's list as downloaded (tab-separated prefix, short name and full name; 24-, 28- and 36-bit blocks, longest match wins; loaded on first call). Update it by downloading https://www.wireshark.org/download/automated/data/manuf over it; Wireshark asks that it be fetched at most weekly. Library code logs through `logging` (the package logger has a `NullHandler`), and only `main()` functions configure output.
- **`scripts/`**: standalone tools that aren't packaged (`sniff.py`, NetBIOS `namescan*.py`).

## Build / test

- Build dependencies: libpcap headers (`libpcap-dev`) and Python dev headers. Metadata is in `pyproject.toml`, and `setup.py` holds the platform-dependent extension settings and the license (see below).
- Build in place: `python3 setup.py build_ext --inplace` puts `pckt/pcap*.so` next to the sources. Install with `pip install .`.
- Debian package: `debian/` builds `python3-pckt` (native format, MIT, all by Matthew Shaw, who committed as Matthew Oertle before 2020; `pckt/manuf` is Wireshark's, GPL-2+) with dh-python and `pybuild-plugin-pyproject`. Run `sudo apt build-dep .` then `dpkg-buildpackage -us -uc -b`; the `.deb` lands in the parent directory, and the tests run against the built extension (`debian/rules` copies `test/` next to it). Bump `debian/changelog` (`dch -v <version>`) together with `version` in `pyproject.toml`. `license` is `dynamic` and set in `setup.py`, as `license_expression` on setuptools 77+ and as `license` before that: the SPDX string form needs 77, newer than Ubuntu 24.04's 68, and 77+ deprecate the `{text = ...}` table form.
- Tests (unittest, no dependencies): `PYTHONPATH=. python3 -m unittest discover -s test`. Run a single one with `PYTHONPATH=.:test python3 -m unittest test_layers.TestDecode.test_udp`.
  - `test_layers.py` needs no build. `test_pcap.py` and `test_stack.py` use pcap files and a fake handle, and skip without the extension. `test_pcap.py` also reads pipes and FIFOs that stall, so a call that holds the GIL fails instead of hanging (through `run_isolated()` or a thread that closes the pipe), and sends SIGINT to blocked reads.
  - `test_live.py` re-runs itself inside `unshare -rn` (an unprivileged user and network namespace, no root). It creates a veth pair, then runs `ghost` against the kernel's own ARP/ping and against dnsmasq, runs the passive mapper, captures through a `create()` handle (and into a `Dumper`, and checks `ip broadcast` gets the device's netmask), and checks that `DNS` queries get answered by dnsmasq and that its responses re-pack exactly. It's skipped when namespaces, `ip`, `ping` or `dnsmasq` are unavailable, and adds about 6 seconds.
- Independent check for new layers: write frames to a pcap file, then run `tcpdump -nn -vv -r file.pcap` (it reports `[udp sum ok]`, `cksum ... (correct)` and `[icmp6 sum ok]`) or tshark (with `-o udp.check_checksum:TRUE` and the like). Reading files doesn't need root.
- Anything else that needs a real interface can be run the same way: `unshare -rn sh -c 'ip link add v0 type veth peer name v1; ...'`. In there, background jobs started by `sh` ignore SIGINT, so start Python children from Python if you need Ctrl-C behaviour.
